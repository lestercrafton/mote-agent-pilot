# Test-only pilot HTTP protocol

No endpoint described here is publicly deployed. Use the candidate root/manifest/OpenAPI after a separately authorized deployment. Origin is operator-pinned HTTPS, never inferred from forwarded headers. Public metadata states candidate/unlaunched/test-only and discloses the complete-fee-cap guard. The old live free Sites service still accepts no payment.

1. GET `/` or `/.well-known/mote.json`, then `/openapi.json`. Discovery and quotes require no token purchase. GET `/health` is process status; `/ready` checks local state, not continuous public RPC availability. Every payment operation verifies fresh chain evidence.
2. POST `/v1/quotes` with `Idempotency-Key` and `{ "payer": "<authorized public address>", "input": { "document": { "count": 3 }, "schema": { "type": "object" } }, "publicSynthetic": true }`. This declaration means the input/result may be public. Unsupported input fails before signing. Reuse the exact key/payer/input on retry. A conflicting request returns 409.
3. Inspect the full EIP-191 offer and EIP-712 quote signatures, pinned configuration, price, deadline and committed result hash. Price is `1000 + 10 * canonicalInputBytes` base units with six decimals; it is a test-unit tariff, not a market valuation. For selected Ethereum Sepolia, the standard payer client can sign and submit only under its separately supplied signer, pinned deployment, persistent journal and exact-operation policy, with a complete signed type-2 native-fee ceiling. The retained Base path refuses before signing because its complete fees cannot be capped. The HTTP server never broadcasts, and neither discovery nor a quote supplies spending authority.
4. For an already authorized, already submitted payment, POST `/v1/orders` with `{ "quoteId": "<signed quote ID>", "transactionHash": "<original hash>", "publicSynthetic": true }` and a stable key. The API verifies exact transaction calldata, payer, zero native value, router, receipt/event bindings, on-chain expiry, canonical block membership, consumed quote state and finalized anchor. Pending returns 202. Uncertain/invalid evidence never authorizes another payment.
5. Retry the same proof/key after a lost response or GET `/v1/orders/<quoteId>`. The result and signed receipt are committed before response. Completed recovery rechecks original historical finality. Time passing beyond quote expiry does not invalidate a payment mined within the deadline.
6. A quarantined restored service can reconstruct a post-backup missing row using POST `/v1/recover` with `{ "offer": "<complete original offer object>", "input": "<original input object>", "transactionHash": "<original hash>", "publicSynthetic": true }`. This needs the full authentic envelope, exact request/result hashes and a finalized proof. Existing keys/transactions cannot be reassigned. Recovery sends no chain transaction. New quotes stay disabled after restore.

POST requires JSON, valid UTF-8, exact fields and publicSynthetic=true; limits include 64 KiB body, five-second body deadline, bounded schema/depth, 32 HTTP inflight requests and 16 service operations. HTTP errors expose codes without private signer/runtime data. Inputs are durable and retrievable without user authentication, so use only intentionally public synthetic fixtures. No public-secret or personal-data workflow is supported.

The test-only service has no remote `/mcp`. Its free `/v1/audit` uses the unchanged shared utility. The portable MCP adapter targets the existing live free Sites API only and contains no payment tools.
