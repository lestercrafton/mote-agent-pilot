## Implemented encrypted handoff and nonlogging boundary

There is no available opaque Render environment-secret transfer integration. Typing raw Q into a browser tool would expose it to automation. No raw-key browser filling, screenshot, terminal command, shell interpolation, `security -w`, API credential creation or authentication-cookie extraction is proposed.

The inactive implementation uses the existing authenticated **Render Dashboard Shell** as a transport for public metadata and authenticated ciphertext only:

1. Verify the exact service dashboard, canonical origin and reviewed deployed commit independently. Put only verified public deployment/dispenser configuration on the approved disk, with pinned hashes. Source/environment strings alone are not host authentication or remote attestation.
2. Start the reviewed importer on that service only after specific approval. It checks Linux/Render identity and public config, writes and fsyncs an exclusive persistent intent before generating a single ephemeral X25519 receiver key in process memory. It prints a public challenge containing the descriptor, random session nonce, receiver public key and at most 120-second lifetime. No HTTP listener, SSH key or new management credential is created.
3. Authenticate and pin both descriptor SHA-256 and challenge SHA-256 from that exact Dashboard Shell. The Mac sealing command accepts only those public pins/challenge and the native helper pin. It checks pins/expiry before Keychain access, reads Q through private FD pipes and emits only an X25519/HKDF-SHA256/AES-256-GCM ciphertext capsule. This is a specific reviewed construction, not a claim of HPKE conformance.
4. Send only that ciphertext capsule through the same shell. The receiver consumes one attempt even on malformed/authentication failure, validates Q's public address, writes a private staging file, fsyncs, publishes with no overwrite and writes a public receipt. The receiver private key expires/is discarded; no reusable transport credential is stored. A 120-second timeout consumes the reserved attempt and may require separately reviewed reconciliation; it does not permit automatic retry.
5. Inspect the exact public receipt and Q address without returning key bytes. Import failures/crashes retain intent/staging/key state; read-only inspection distinguishes states. No automatic reimport, overwrite or cleanup is allowed. Unresolved states may remain blocked indefinitely.
6. The new `scripts/testnet-file-server.mjs` checks public configuration and source/destination binding before loading Q. It passes Q only in an ephemeral JavaScript object to the existing starter and never assigns global `process.env` or spawns a secret-bearing child. The object property is removed afterward; the actual signer necessarily retains signing material in memory. A source-commit change intentionally fails this binding and needs a reviewed migration.

The only secret leaving the Mac is **Q**, carried encrypted to this exact host, then decrypted into the restricted file and service memory. A/P private keys never leave the Mac. Public addresses, signed transaction bytes, transaction hashes, quote/receipt signatures and synthetic input are public by design. Browser/tool history may retain public challenges/ciphertext and public receipts; it must never contain raw Q. Helpers use fixed redacted errors without nested exception output and never log raw keys. Do not run debugging/profiling/core-dump/terminal commands that print private files or signer objects. Complete protection against a compromised service, provider, same-user Mac process or memory dump is not claimed.

Render says disks and daily snapshots are encrypted at rest, but the service and provider administrators can access plaintext in use. Disk snapshots may retain a copy of Q; deleting the live file does not promise provider backup erasure. The application SQLite backup tool does not include the separate quote directory. Native login-Keychain backup remains the proposed recovery copy. These are custody tradeoffs, not a managed secret vault. See [Render disks](https://render.com/docs/disks), [automatic environment metadata](https://render.com/docs/environment-variables) and [API authentication](https://render.com/docs/api).
