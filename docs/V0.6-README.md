# Mote v0.6.0-faucet.1 — isolated test-token dispenser candidate

This adds a **pre-funded, keyless onchain dispenser** to the reviewed v0.5 Ethereum Sepolia payment prototype. It has not been published or deployed. The existing live free utility and public v0.5 source remain unchanged. No keys, faucet claims or public transactions were created.

The dispenser transfers existing fixed-supply test MOTE: it never mints. Compiled maxima are **10 test MOTE per address** and **10,000 test MOTE total per dispenser**; the proposed configuration uses both maxima. Each address can claim once by calling `claim()` with no arguments or native value. There is no owner, privileged payout signer, reset, upgrade or withdrawal function. Callers pay their own test ETH gas.

An address limit is **not identity or Sybil protection**. One actor with many funded addresses can exhaust the reserve. Extra funding does not increase the immutable payout cap; excess tokens are stranded. Observable transfer-tax and balance-delta discrepancies revert, but dishonest/mutable/rebasing tokens remain unsupported. Use only the independently verified MoteToken. This is no-value test infrastructure, not a public token sale, value promise or evidence of adoption.

## Run and inspect

Use Node 24.22.2 and install development dependencies for isolated contract tests:

```sh
npm ci --ignore-scripts
npm test
npm run compile:dispenser
npm run demo:sepolia
```

The separate compiler writes only `artifacts/MoteTestDispenser.json`, including complete compiler input. Existing token/router sources, artifacts, payment client and service behavior are unchanged. Tests use known public local fixtures, never a public network. **330/330 full regression tests passed** on Node24.22.2; an independent review also passed all **18 new contract/plan tests**. See [verification record](docs/faucet-verification-v0.6.json) and [full log](docs/faucet-full-tests-v0.6.txt).

Prepare an unsigned add-on plan from a completed public configuration:

```sh
node scripts/prepare-dispenser.mjs --config PUBLIC_DISPENSER_CONFIG.json --out NEW_DISPENSER_PLAN.json
```

`config/dispenser.template.json` has null identities, not fake deployment addresses. The planner pins the expected token runtime hash, constructor limits, predicted address and exact reserve transfer. It does **not** verify that hash against a chain, supply fees, grant authority or broadcast. The original two-contract deployment verifier does not verify this add-on.

## Agent onboarding boundary

After a separately reviewed deployment and reserve funding, any agent with its own authorized wallet and test ETH can use the public ABI to claim. It needs no server approval or custodian signature. Before launch, the service must publish the verified dispenser address/token/configuration and agents must enforce their own chain, destination, calldata and native-fee policy.

There is currently no deployed dispenser address, active discovery advertisement, automatic claim integration in `TestnetMoteClient`, test-ETH faucet service or public proof. The original payment journal does not reserve fees for a claim; do not share its wallet nonce authority with a separate claim process. Complete/reconcile a claim under separate valid wallet policy before starting a payment journal. Unknown sends must not trigger a fresh claim from another identity automatically.
