# v0.6.0-faucet.1 handoff

This isolated candidate adds a pre-funded onchain MoteTestDispenser and unsigned preparation only. It does not change the reviewed v0.5 deployment/source, token fixed supply, router, payment client or hosted free service. No persistent key, public faucet claim, external transaction or deployment occurred.

`MoteTestDispenser` has immutable token, claimAmount and distributionCap. Hard compiled maxima are 10MOTE/10000MOTE (six decimals); smaller positive divisible configurations support fixtures. Only msg.sender receives one claim. SafeERC20, effects before transfer, ReentrancyGuard and exact observable sender/recipient balance changes protect the supported transfer. Failure rolls back both claim eligibility and cap usage. Balance deltas do not authenticate a malicious token; intended use is the verified non-upgradeable MoteToken only. There is no withdrawal even for accidental excess funding.

The separate compiler exports a reproducible artifact with all Solidity sources and immutable references. Original token/router files remain byte-identical. `src/dispenser-plan.mjs` and `scripts/prepare-dispenser.mjs` produce exactly two unsigned requests: creation, then an exact cap-sized token transfer. The token runtime hash is a caller pin, not verified evidence. The script cannot sign, connect to RPC, overwrite an output plan, authorize a transaction or turn a template into a live address.

Local tests cover exact payout/event/supply preservation, replay, competing last claim, empty/partial-funding retry, multiple-address exhaustion, surplus/topup cap, constructor constraints, transfer taxes, false-after-mutation/revert/no-op token behavior, caught/bubbled reentry and native-value rejection. They explicitly demonstrate Sybil exhaustion. Plan tests cover exact construction, mutation rejection, bounds, duplicate JSON keys and new-file-only output. The full Node24.22.2 suite passed 330/330 tests, no skipped tests, in80.33seconds; independent18/18focused tests also passed. The preserved original local demo passed. See faucet-verification-v0.6.json and faucet-full-tests-v0.6.txt.

Before any public launch, a separately reviewed deployment/verification wrapper must pin the dispenser code and immutable values alongside the existing token/router, publish an honest active discovery reference, and keep caller gas-policy/nonce ownership explicit. The existing payment journal/client does not automatically claim or account claim fees. Test ETH remains an external prerequisite. Per-address limits do not guarantee fair distribution or enough reserves for unknown future agents.

The signer-provisioning report's earlier six-transaction controlled test does not authorize this add-on. With a dispenser, a proposed bootstrap is eight calls: token, router and dispenser creations; exact reserve funding; bounded test-gas transfer to the controlled payer; payer claim, exact approval and one payment. This requires a fresh concrete unsigned envelope and its authorization, never an assumed extension. No real-money fees, new subscriptions, keys or public transactions are authorized by these files.

The Render service-creation rejection remains unresolved. Its prepared maintenance-only draft was not submitted again. This candidate is delivered separately for review and must not silently replace v0.5's immutable public source/archive.
