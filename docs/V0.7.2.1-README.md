# Mote v0.7.2-custody.1 — inactive custody preparation

This separate candidate prepares an encrypted, one-time quote-key handoff through the existing authenticated Render Dashboard Shell and a restricted file loader. No real key, native Keychain access, host receiver, secret transfer, faucet claim or public transaction was performed. The live service remains maintenance-only on v0.7.1-resource.1; this candidate is not published or deployed.

Read the [complete signer approval proposal](docs/SIGNER-PROPOSAL-v0.7.2.md) and [eight-transaction manifest](docs/SIGNER-EIGHT-TRANSACTIONS.json). The manifest deliberately uses roles and derived addresses: actual keys do not exist, so it is not a signable transaction manifest. All prior chain, exact-price, finality, journal and fee guards remain required.

The new handoff avoids exposing raw Q through tool arguments, terminal output, screenshots or a new management API credential. It does not protect a compromised Mac/host, prove remote attestation, or make the service production-ready. Real native Keychain ACL compatibility remains untested and requires the proposed specific approval. File custody would replace the previously proposed persistent Render environment-secret destination; it is not already approved or installed.

Use Node 24.22.2. `npm ci --ignore-scripts`, `npm test`, `npm run demo:onboarding` and `npm run demo` use only public local fixtures. The new focused tests use fixed public scalar1 and fixed X25519 fixtures; they do not generate real credentials. No real activation command should be run as a test.

The existing useful service, payment/dispenser design, limits and local quickstart remain in [v0.7.1 documentation](docs/V0.7.1-README.md). See [handoff](docs/HANDOFF.md) for current evidence and limitations. No public cryptocurrency settlement, outside adoption, token value, peg, redemption or investment return is claimed.
